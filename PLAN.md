# Plan: Text Input — color while typing, Enter = newline, resizable pending box

_Locked via grill (compressed) — by Claude + Bruno. Terms per CONTEXT.md. Applies to BOTH input surfaces: Selection Overlay (Quick Annotation) and post-capture editor._

## Goal

While typing a text annotation, the text shows the designated palette color (not black); Enter inserts a newline instead of committing; and the pending text box is resizable with handles — the box's rect becomes the annotation's wrap `bounds`. Commit gestures: click outside, ⌘↩, or Esc — all keep the typed text (empty text discards the annotation). Committed rendering is untouched (`drawTextRun` already wraps within `bounds` and applies color correctly).

## Facts (verified)

- Color loss is input-time only. Overlay: `field.textColor = .black` hardcoded (`CaptureController.swift:2000`). Editor: `inlineTextField` has no `.foregroundStyle` (`AnnotationEditor.swift:1179-1207`). Commit paths already store `style.color` correctly.
- Enter-commits is structural: overlay uses a single-line `NSTextField` whose `doCommandBy` intercepts `insertNewline` → `commitFieldEditor()` (`CaptureController.swift:2010-2020`); editor uses single-line SwiftUI `TextField` with `.onSubmit` → resolve (`AnnotationEditor.swift:1189-1192`).
- `TextAnnotation.bounds` is a `NormalizedRect`; renderer wraps via `CTFramesetter` in that rect (`ImagePipeline.swift:307-335`). Editor already resizes COMMITTED text via `AnnotationResizeHandle` corner handles (`AnnotationEditor.swift:1143-1164`, `1328-1330`). No model changes needed.

## Approach

Shared contract first: ONE multiline text-input behavior, hosted twice. Enter → newline; ⌘↩ → commit; Esc → commit; click outside → commit; empty (trimmed) text on commit → annotation discarded, otherwise the ORIGINAL untrimmed string is stored (trimming is used ONLY for the emptiness test — change both commit paths, `CaptureController.swift:2031` and `AnnotationEditor.swift:545`).
- **Key routing seam (pure, unit-tested)**: new `TextInputKeyDecision.action(for: Selector, commandModifier: Bool) → .insertNewline | .commit | .pass` — `insertNewline` without ⌘ → `.insertNewline`, with ⌘ → `.commit`; `cancelOperation` → `.commit`; anything else `.pass`. Both delegate paths call it: overlay via `NSTextFieldDelegate.control(_:textView:doCommandBy:)` (existing hook, `CaptureController.swift:2010`), editor via `NSTextViewDelegate.textView(_:doCommandBy:)`.
- **Exact insertion semantics (per surface — asymmetric on purpose)**: overlay (NSTextField's field editor): `.insertNewline` → call `textView.insertNewlineIgnoringFieldEditor(nil)` and **return true** (returning false would let the field editor's default Return END editing); editor (real NSTextView): `.insertNewline` → **return false** (AppKit's default inserts exactly one newline; manual insert + true would double-insert). `.commit` → perform commit and return true on both. `.pass` → return false on both.
- **Minimum pending size — ONE clamp layer per surface**: `beginText(rect:minSize:style:)` — the VIEW computes the normalized `minSize` from the image `PixelSize` (`min(60, w)/w × min(28, h)/h`, capped at 1.0) and passes it in; pending state stores it, and one state-side clamp helper serves BOTH `resizePendingText` and auto-grow. Overlay's single clamp layer works in display points — explicitly the same pixel invariant converted: 60/28 px ÷ display scale (so physical minimum matches the editor across Retina scales) AND clamps the whole field frame — initial 220 pt frame, every auto-grow, every handle resize — to the committed selection rect (otherwise `OverlayAnnotationConversion`'s fully-inside rule silently drops the annotation near edges/narrow selections). A zero/degenerate rect (which `drawTextRun` renders as nothing) is unrepresentable.
- **Auto-grow**: height grows to fit wrapped text ONLY until the person first resizes manually; after that the rect is authoritative. Measurement paths: editor — `layoutManager.usedRect` in the Coordinator's `textDidChange`; overlay — `controlTextDidChange` (delegate already wired) measuring `cell.cellSize(forBounds:)` at the current width, then updating `field.frame` (through the selection-rect clamp) and repositioning handles. `userSized` is a field OF the pending-text state (overlay: field-editor session state; editor: inside the pending-text struct) — NOT view-local `@State` — so SwiftUI view recreation cannot reset it; it is set at the end of every pending-handle drag.
- Color: new tiny shared helper `RGBAColor.nsColor` (`NSColor(srgbRed:green:blue:alpha:)` — no such conversion exists today).
- Scope note: `PendingAnnotationText`/pending-state changes are TRANSIENT editor state only; the persisted `AnnotationDocument` schema is unchanged.

1. **Overlay field editor → multiline + colored + resizable** (`CaptureController.swift`):
   - `beginFieldEditor`: `usesSingleLineMode = false`, cell wraps, `field.textColor = style.color.nsColor` (new helper).
   - `doCommandBy`: `insertNewline` → ⌘ pressed (`NSApp.currentEvent`) ? `commitFieldEditor()` : `textView.insertNewlineIgnoringFieldEditor(nil)`; `cancelOperation` (Esc) → `commitFieldEditor()`. `cancelFieldEditor()` remains only for programmatic teardown (operation cancel/overlay teardown).
   - `SelectionOverlayPrecedence.action` (`CaptureGeometry.swift:328-356`): field-editor-active rows — `.escapeKey → .commitFieldEditor`, `.returnKey → .ignore` (handled inside the field editor). Update its unit tests.
   - Resizable pending box: **dedicated handle subviews** (8, positioned by the pure `SelectionHandle` geometry, owned by the overlay view, sitting above the field) — each handle receives its own mouseDown/drag directly, so events never depend on the parent's `mouseDown` (the NSTextField subview swallows clicks in its frame; the existing "any mouseDown commits" path at `CaptureController.swift:1652-1657` stays for clicks that DO reach the parent = click-outside commit). **Handle lifecycle is field-editor lifecycle**: created in `beginFieldEditor`, repositioned on every field frame change (drag or auto-grow), removed in `commitFieldEditor`, `cancelFieldEditor`, and `setInert`. Drag updates `field.frame` via `SelectionHandle.resized` with the minimum-size clamp; sets `userSized`. On commit, draft `.text` bounds convert from **`field.frame` directly** — the current `fieldEditorOrigin`-based reconstruction (`CaptureController.swift:2026-2038`) is removed, otherwise a dragged/resized field would persist its original position.
2. **Editor pending text → same contract via NSViewRepresentable** (`AnnotationEditor.swift`):
   - Replace the single-line SwiftUI `TextField` with a thin `NSViewRepresentable` wrapping a multiline `NSTextView` (no scroll view chrome, background/inset styled like today's field): `textColor` set directly from `model.style.color` (deterministic glyph color — no reliance on `.foregroundStyle` through `TextEditor`); key handling via `NSTextViewDelegate.textView(_:doCommandBy:)` → `TextInputKeyDecision`. Exact wrap config: `isRichText = false`, `isHorizontallyResizable = false`, `isVerticallyResizable = true`, `textContainer.widthTracksTextView = true`, `heightTracksTextView = false`, `containerSize = (fieldWidth − inset, .greatestFiniteMagnitude)` — plus a test asserting text at a constrained width actually wraps (`usedRect` height > single-line height).
   - **Focus bridge (Coordinator, bidirectional)**: activation guarded — if `window == nil` at mount, defer `makeFirstResponder(textView)` via `viewDidMoveToWindow`/main-queue hop; Coordinator observes `textDidEndEditing`/first-responder resignation and reports through the focus binding (replacing `.focused($textFieldIsFocused)` semantics) → drives the existing focus-loss resolve. Reverse path: commit/cancel resigns first responder and returns key focus to the canvas; binding synced both directions. `textDidChange` re-measures `layoutManager.usedRect` for auto-grow while `!userSized`.
   - Click-outside commit: explicit background-tap path covering the FULL canvas (a hit target behind the image and overlays — letterbox clicks included), excluding the text view and its handles → `resolvePendingText()`; the existing focus-loss `.onChange` stays as backup.
   - Resizable pending box: `AnnotationResizeHandle` corner GEOMETRY reused, but with a **pending-specific gesture and new state API `resizePendingText(handle:to:)`** (the existing `resizeSelection` machinery is hard-wired to committed `AnnotationItem`s — pending text never goes through it); an `isResizingPending` flag suspends focus-loss resolution for the duration of a handle drag, resolve re-enabled after the drag commits the new rect and sets `userSized`.
   - `pendingText` state gains a **`NormalizedRect`**; since `CanvasTransform` lives in the view layer, `AnnotationEditorState.beginText` changes signature to `beginText(rect:style:)` — the VIEW computes the clamped normalized default rect (today's 220 pt-wide frame converted at the anchor through `CanvasTransform`, y-orientation + insets included) and passes it in. Resolve commits that rect as `TextAnnotation.bounds`. All state math normalized; canvas pt only at the view layer.
   - `cancelPendingText()` remains for programmatic paths (tool switch/document reset) — no user gesture discards typed text.
3. **Tests** (house style, updates + new):
   - `CaptureGeometryTests`: `SelectionOverlayPrecedence` field-editor rows (Esc → commit, Return → ignore).
   - `AnnotationModelTests`: pending-text rect resize → committed `TextAnnotation.bounds` equals resized rect; Esc-path resolve keeps text; empty text discards; multiline text (`"a\nb"`) round-trips through commit.
   - `ImagePipelineTests`: already proves color + wrapped layout at render; add one multiline assertion (text with `\n` renders pixels in both line regions) if not present.
   - `AnnotationModelTests`: `beginText(rect:style:)` + pending rect normalization round-trip through `CanvasTransform` (y-flip correct); exact minimum-size clamp incl. image-smaller-than-min case; untrimmed-string storage (`"  a  \n"` commits as-is; `"   "` discards); `userSized` stops auto-grow.
   - New: `TextInputKeyDecision` pure tests (Enter/⌘↩/Esc/other → newline/commit/commit/pass) — the deterministic seam for key routing on both surfaces.
   - New AppKit seams (offscreen, deterministic — house precedent: `ManualScrollSessionTests` NSEvent synthesis): Coordinator tests driving `textView(_:doCommandBy:)` with real selectors on an offscreen `NSTextView` (newline actually inserted once; ⌘↩/Esc trigger commit callback); overlay handle subview lifecycle asserted via offscreen `NSWindow` (added on begin, repositioned on frame change, removed on commit/cancel/setInert); `resizePendingText(handle:to:)` state tests incl. normalized `minSize` clamp; **color propagation** (field/`NSTextView` `textColor` equals `style.color` at begin); **auto-grow observable** (multi-line text change increases measured frame height, clamped to selection).
   - Overlay: unit-test handle placement + `SelectionHandle.resized` + min-clamp via pure geometry functions; AppKit event delivery (handle subview vs field vs parent) is manual QA.
4. **Manual QA**: extend `docs/manual-qa/quick-annotation.md`, one row per gesture path on each surface — palette color while typing; Enter newline; ⌘↩ commit; Esc commit (text kept); click-out commit; handle resize (no mid-drag commit, text wraps, min size holds); auto-grow stops after manual resize; committed image matches preview.

## Key decisions

- Esc commits (keeps text) — accidental data loss beats stale cancel semantics; discard = delete text then commit-empty.
- Resize sets wrap rect at constant font (renderer already wraps in `bounds`); font size stays a style property.
- No model/schema changes; no renderer changes.

## Out of scope

- Rich text, font picker, per-character color; resizing committed overlay draft items other than the active field; changing emoji field behavior (stays single-shot).
