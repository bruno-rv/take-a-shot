# Quick Annotation reuses the editor's annotation model and renderer

The Selection Overlay is pure AppKit drawing over the live screen, while the post-capture editor is SwiftUI. Rather than build a second annotation system for the overlay (or port the overlay to SwiftUI), Quick Annotation shares the editor's annotation model and rendering: `AnnotationRenderer`'s per-item drawing is refactored into shared CGContext render primitives with two thin adapters — a document adapter (normalized → image pixels, the existing Bake path) and a draft adapter (display-global overlay points → view coords, used by the overlay's `draw(_:)`). At Confirm, the overlay hides, the region is captured, and the document adapter Bakes the resulting Annotation Document onto the captured pixels; the document itself is handed to the editor still editable. One model, one set of primitives, two surfaces.

**Consequences**: `NormalizedPoint`/`NormalizedRect` clamp to 0–1, so `AnnotationItem` cannot represent pre-capture geometry. Quick Annotation therefore holds items in an unclamped, display-global `OverlayAnnotationDraft` (never persisted) and converts to normalized `AnnotationItem`s exactly once, at Confirm, against the final selection rect — resizing the selection after annotating keeps annotations anchored to screen content, not stretched. Out-of-selection draft items follow per-type rules at Confirm (previewed live by dimming): filled highlight/blur rectangles are intersected with the selection; arrows, text, outline shapes, and Step Badges are kept only if fully inside — partially- or fully-outside ones are dropped, because generic clamping would corrupt them. The Annotation Document never holds out-of-range geometry, and it is constructed only after capture returns, using the fresh `CapturedImage.id`.
